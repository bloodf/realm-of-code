**Ideias principais**
- Um banco de dados relacional guarda dados em **tabelas** (linhas e colunas). **SQL** é a linguagem para fazer perguntas.
- `SELECT name, level FROM knights;` escolhe colunas. `SELECT *` escolhe todas.
- `WHERE` filtra linhas: `=`, `<>`, `>`, `<=`, `AND`, `OR`, `NOT`, `IN (...)`, `LIKE 'A%'`, `IS NULL`.
- Texto usa aspas simples: `WHERE name = 'Ada'`.
- Bancos populares: PostgreSQL, MySQL, SQLite, SQL Server.
~~

**Ideias principais**
- Uma **chave primária** (`id`) identifica cada linha. Uma **chave estrangeira** (`house_id`) aponta para uma linha de outra tabela.
- Uma casa tem muitos cavaleiros (**um-para-muitos**). Muitos-para-muitos precisa de uma tabela de junção (ex.: `knight_skills`).
- `JOIN ... ON a.x = b.y` (INNER) mantém só as linhas que combinam nas duas tabelas.
- `LEFT JOIN` mantém todas as linhas da tabela da esquerda; o que não combina vira `NULL`.
- Nomes curtos: `FROM knights k JOIN houses h ON k.house_id = h.id`.
~~

**Ideas clave**
- Una **clave primaria** (`id`) identifica cada fila. Una **clave foránea** (`house_id`) apunta a una fila de otra tabla.
- Una casa tiene muchos caballeros (**uno a muchos**). Muchos a muchos necesita una tabla intermedia (p. ej. `knight_skills`).
- `JOIN ... ON a.x = b.y` (INNER) se queda solo con las filas que coinciden en las dos tablas.
- `LEFT JOIN` conserva todas las filas de la tabla de la izquierda; lo que no coincide se vuelve `NULL`.
- Nombres cortos: `FROM knights k JOIN houses h ON k.house_id = h.id`.

**Ideias principais**
- `INSERT INTO t (a, b) VALUES (1, 'x');` `UPDATE t SET a = 2 WHERE id = 1;` `DELETE FROM t WHERE ...;`
- Use **sempre** WHERE com UPDATE e DELETE, senão todas as linhas mudam!
- `CREATE TABLE` com tipos (INTEGER, TEXT, REAL) e restrições (PRIMARY KEY, NOT NULL, UNIQUE, REFERENCES, DEFAULT). Índices aceleram as buscas.
- Em aplicativos: consultas parametrizadas (nunca concatenação de strings), ORMs (Prisma, Drizzle), transações, migrações.
- Bancos **NoSQL** (MongoDB, Redis...) guardam documentos ou pares chave-valor; ótimos para dados flexíveis ou muito rápidos.
~~

**Ideas clave**
- `INSERT INTO t (a, b) VALUES (1, 'x');` `UPDATE t SET a = 2 WHERE id = 1;` `DELETE FROM t WHERE ...;`
- Usa **siempre** WHERE con UPDATE y DELETE, ¡o cambiarán todas las filas!
- `CREATE TABLE` con tipos (INTEGER, TEXT, REAL) y restricciones (PRIMARY KEY, NOT NULL, UNIQUE, REFERENCES, DEFAULT). Los índices aceleran las búsquedas.
- En aplicaciones: consultas parametrizadas (nunca concatenar strings), ORMs (Prisma, Drizzle), transacciones, migraciones.
- Las bases de datos **NoSQL** (MongoDB, Redis...) guardan documentos o pares clave-valor; geniales para datos flexibles o muy rápidos.
